EJERCICIO: "ANÁLISIS DE INTERFACES"
Análisis estructural y de comportamiento responsivo de un sitio web y una plataforma web, evaluando sus decisiones de diseño y layout frente a distintos viewports.
1. Sitio Web: Casiopea (Wiki eAD)

A. Comportamiento al hacer scroll:
La barra superior y el menú lateral de navegación global suelen mantenerse fijos o fácilmente accesibles en resoluciones de escritorio para facilitar la exploración. El bloque de contenido central, que alberga la documentación, fluye de manera independiente al hacer scroll.

B. Distribución de columnas:
Al inspeccionar con las herramientas de desarrollador, se observa una estructura clásica asimétrica. Un porcentaje menor del ancho (aprox. 20-25%) se reserva para el sidebar o navegación, mientras que el espacio restante aloja el contenido principal, estructurado mediante un sistema de bloques o flexbox.

C. Reacción al tamaño móvil:
El layout reacciona mediante media queries. El menú lateral colapsa (convirtiéndose en un menú hamburguesa o desplazándose hacia el fondo de la página), permitiendo que la columna de contenido principal se expanda al 100% del ancho de la pantalla para optimizar la lectura.

D. Decisiones y ajustes:
Las decisiones son muy apropiadas para la naturaleza de una wiki documental, donde priorizar la lectura es clave. Como ajuste, aumentaría ligeramente el padding lateral en la versión móvil y ajustaría la jerarquía tipográfica para evitar que grandes bloques de texto se sientan abrumadores en pantallas pequeñas.

2. Plataforma Web: Navegador Académico

A. Comportamiento al hacer scroll:
A diferencia de las interfaces modernas, la estructura es rígida. La mayoría de los elementos (incluyendo cabeceras de tablas) desaparecen hacia arriba al hacer scroll, lo que hace que el usuario pierda el contexto de los datos si la lista de información es muy extensa.

B. Distribución de columnas:
Inspeccionando el DOM, su arquitectura está fuertemente basada en estructuras tabulares antiguas y contenedores estáticos. Divide la interfaz en un panel lateral para el menú de usuario y una extensa área de trabajo central para el despliegue de datos financieros o académicos.

C. Reacción al tamaño móvil:
El layout presenta una baja adaptabilidad (carece de un enfoque mobile-first). Al reducir el viewport al tamaño de un teléfono, los contenedores no fluyen de forma apilada. En su lugar, el diseño se rompe o fuerza al usuario a utilizar scroll horizontal, lo cual entorpece gravemente la usabilidad táctil.

D. Decisiones y ajustes:
Las decisiones tecnológicas están desactualizadas para los estándares actuales. El principal ajuste sería migrar la estructura tabular a un sistema CSS Grid fluido, permitiendo que en versión móvil el menú pase a ser desplegable y la información se agrupe en tarjetas apiladas en una sola columna. Además, aplicaría position: sticky; a los encabezados de las tablas de notas para no perder la referencia visual al bajar.
